# staticcheck 第二批安全修复计划

## 目标

在 `8bff3c7` 基线后，继续处理已确认的错误传播、资源释放与私有无调用方残留；不改变客户端响应写失败语义、弃用路由、数据库迁移、缓存/额度或上游协议 DTO。

## 实施与验证

| 项目 | 结果 |
| --- | --- |
| Ali 图片异步任务响应读取 | 读取 `resp.Body` 失败立即记录并返回，避免被后续 JSON 解码赋值覆盖。 |
| multipart 图片文件生命周期 | 图片读取后无论成功或失败均关闭文件句柄；关闭失败显式返回。 |
| 私有死代码 | 删除 `cleanClaudeToolParameters` 与 `trimModelThinking`，两者均无调用方。 |
| 定向验证 | `go test ./relay/helper ./relay ./relay/channel/ali` 通过。 |
| 完整隔离验证 | Bun 生产构建、Go 全量测试、`go build -trimpath`、`go vet`、全库 `go test -race` 均通过。 |
| staticcheck | 物理日志行由 127 降至 124。 |

## 保留边界

Baidu、Cohere 与 Zhipu 的 `Writer.Write` 返回值仍不在本批修改范围：它们涉及客户端断连后计费、usage 记录和 response 语义，需先统一 relay 策略。弃用 API、数据库迁移、Redis/cache、quota/TTS、模型倍率和上游 DTO 同样保留待专项审计。
