# 渠道状态与模型列表可见性修复

## 目标

使对外 `/v1/models` 及后台启用模型列表只展示至少由一个**可用渠道**提供的模型。手动禁用或自动禁用渠道的模型应立即隐藏；渠道恢复为 enabled 后，模型应重新出现。新增渠道在请求未显式提供状态时默认使用 enabled，并在能力生成后立即可见。

## 实施范围

| 文件 | 调整 |
| --- | --- |
| `model/ability.go` | 模型聚合、映射模型和启用模型详情查询 JOIN `channels`，仅接受 `channels.status = enabled` 且 `abilities.enabled = true`。 |
| `controller/model.go` | Token 模型限制列表与当前可用模型求交集，避免限制集合绕过渠道状态过滤。 |
| `controller/channel.go` | 新增渠道的 status 为 unknown/零值时显式设置为 enabled，再生成 abilities。 |
| `controller/model_list_test.go` | 覆盖普通列表、Token 限制列表、手动/自动禁用隐藏、恢复显示和新增渠道默认可见。 |

## 安全与兼容边界

不删除任何渠道或模型数据，不修改已禁用渠道状态，也不改变用户 Token 的模型限制配置；仅改变模型列表的可见性和新增渠道的零值默认状态。映射模型必须来自可用渠道，避免通过映射关系泄露已禁用渠道的请求模型。

## 结果

`/v1/models` 的普通路径和 Token 模型限制路径均只展示可用渠道模型；手动禁用或自动禁用渠道后立即隐藏，恢复 enabled 后重新显示。新增渠道省略 status 时显式默认为 enabled，生成的 ability 也保持启用，因此模型立即可见。
