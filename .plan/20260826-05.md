# 依赖一致性与剩余计划收尾

## 执行规则

- 本批只处理经 `go mod tidy -diff` 证明的模块声明一致性问题；不修改业务行为。
- 前端构建优先使用 Bun；后端嵌入构建在隔离副本中进行。
- 不恢复 quota/billing/ratio、音频/视频/音乐/异步任务或 MySQL/PostgreSQL 支持。
- 不把渠道 adaptor 为满足统一接口而保留的 `TODO implement me` 方法误删除；其是否实际可支持某能力需以路由、接口及适配器调用链单独审计。

## Current State

上一批 `898e95e` 已使隔离副本的 `staticcheck ./...` 输出为零。重新审计工作树后，唯一可机械修复的差异是 `go.mod` 把未被项目源码直接导入的 `golang.org/x/sync` 标记为直接依赖；`go mod tidy -diff` 要求将其移到 indirect 区块。`go mod why` 显示其仍通过依赖图保留，因此不能移除版本条目。

## Risks and Explicit Deferrals

`golang.org/x/sync` 是传递依赖，错误地完全删除会导致模块图不完整；本批仅修正其直接/间接分类。项目源码中发现的渠道 adaptor `TODO` 多数是统一适配器接口的显式不支持实现或协议能力缺口，不能视为 U1000 孤立代码；为避免破坏现有渠道行为，本批不删除或填充这些方法。

## Rollback Plan

若 tidy 后任一构建或测试失败，恢复 `go.mod`/`go.sum` 的本批变动，并报告实际依赖路径；不回退已验证的 U1000 清理提交。
