# 58 条低风险 staticcheck 收尾计划

## 目标

实施已评估为低风险、语义等价或包私有签名重排的 58 条 staticcheck 诊断，不触及 API 错误文本和仍需专项验证的 U1000。

## 已完成修复

| 分类 | 结果 |
| --- | --- |
| 控制器冗余控制流 | 删除 `controller` 五个文件中 37 个函数末尾冗余 `return`。 |
| 类型、nil 和 append 化简 | 处理 DTO、请求验证、流转换、OpenAI/Ollama、token 统计、模型查询、AWS header 解析等 18 项等价诊断。 |
| 错误与类型安全 | 将三处 `errors.New(fmt.Sprintf(...))` 改为 `fmt.Errorf(...)`；request context 改用私有 typed key；RelayFormat 常量显式类型化。 |
| adapter 内部质量 | MokaAI embedding 使用显式结构体类型转换；Ali `updateTask` 将 error 调整为最后返回值并同步唯一调用方。 |
| 通用层 | Interface2String 改用带类型绑定的 switch；请求路径后缀清理无条件使用 `TrimSuffix`。 |

## 验证

- 已先运行覆盖修改域的定向 Go 测试。
- 最终隔离副本通过：Bun 前端生产构建、`go test ./...`、`go build -trimpath ./...`、`go vet ./...`、`CGO_ENABLED=1 go test -race ./...`。
- staticcheck 物理日志行由 104 降至 **41**；不再包含本批界定的 58 条低风险规则。

## 保留范围

剩余 41 行均为 5 条 API 可见错误字符串风格诊断和 36 条 U1000。后者按迁移/运维、quota/cache/TTS、上游协议 adapter、功能开关分组，必须在专项测试下决定删除或保留，不应为追求零警告而批量删除。
