# quota、货币与价格完全移除及 SQLite 迁移计划

## 执行规则

本批依据用户确认执行**完全清理模式**。目标不是继续隐藏公开字段，而是删除源码中的 quota、货币、价格和倍率业务语义，并在启动迁移中物理清除对应 SQLite 列与旧 option 数据。必须保留用户账户、API Token 密钥、渠道配置、请求日志以及 prompt/completion/total tokens 与 request count 统计。

每个存在旧 schema 的 SQLite 数据库将在变更前创建同目录、带时间戳的备份文件；只有检测到本批遗留列、表或 option 时才触发备份与迁移。内存数据库和 URI 数据源不执行文件备份。迁移使用 GORM SQLite migrator，不依赖 MySQL/PostgreSQL 或外部 sqlite CLI。

## 确认的迁移范围

| 领域 | 物理/源码清理 | 保留或替代 |
| --- | --- | --- |
| users | 删除 quota、used_quota、aff_quota、aff_history 列及邀请奖励状态 | 账户身份、分组、请求次数、登录设置。 |
| tokens | 删除 remain_quota、unlimited_quota、used_quota 列和鉴权分支 | Token key、过期时间、模型限制、IP 限制、分组与访问时间。 |
| logs | 删除 quota 列和计费日志语义 | 请求日志、模型、渠道、prompt/completion tokens、耗时。 |
| quota_data | 重命名为 usage_data，删除 quota 列与 quota 命名 | token_used 与 count 的按小时统计。 |
| channels | 将 `used_quota` 迁移为 `used_tokens`，保留历史统计数值 | 渠道 tokens 消耗统计。 |
| options/Redis | 删除价格、倍率、quota、货币旧 option；删除用户/token quota 缓存键 | 认证、请求限流与 tokens 指标缓存。 |
| relay/service | 删除 PriceData、预消费、退款、余额不足和固定零值兼容逻辑 | 中继请求、Token 鉴权、tokens 使用记录。 |
| 前端/API | 删除价格/倍率/额度管理、请求与显示残留 | channels、tokens、日志和 tokens dashboard。 |

## Rollback

启动迁移前生成的 `<database>.pre-lite-schema-<UTC>.bak` 是唯一完整 rollback 数据源。若迁移异常，程序启动失败并保留原库与备份；恢复时以备份替换数据库主文件，并同时移除与其不匹配的 WAL/SHM 辅助文件后重启。迁移成功后不再有 quota/价格业务代码可解释旧列，因此回滚代码应通过 Git 回退到本提交之前版本后再恢复备份。
