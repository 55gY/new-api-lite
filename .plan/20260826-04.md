# 剩余 23 条 U1000 专项清理计划

## 评估与处置

剩余 U1000 分为六组：SQLite-only 启动/迁移残留、Lite quota/cache 残留、Redis 当前性能桶残留、Jimeng/Zhipu 协议残留、Codex 状态 helper，以及历史 model ratio 表。代码和调用链检索确认这些私有符号均没有运行时调用；在项目 SQLite-only、无 quota/billing、无音频/TTS 的既定边界下，可安全删除。

| 组 | 已删除内容 | 处置理由 |
| --- | --- | --- |
| 启动/迁移 | `commonTrueVal`、`commonFalseVal`、`logKeyCol`、`createRootAccountIfNeed`、`migrateLOGDB` | 移除多数据库列值残留、无调用独立日志迁移和默认 `root/123456` 创建逻辑；现有 setup 流程保持。 |
| quota/cache | token/user quota 扣减、Redis quota 写入、status 单字段 cache helper 共 10 项 | Lite 项目不保留 quota/billing；认证、group 与公开 cache 路径未移除。 |
| 性能 Redis | `redisCounters`、`parseRedisInt`、`mergeRedisActiveBuckets` | 当前查询从未合并活跃 Redis 桶；删除不会改变现有行为。 |
| 协议残留 | Jimeng `getPayloadHash`、Zhipu 4V `tokenData/zhipuImageRequest` | 私有且无调用，未参与当前请求/响应序列化。 |
| Codex | `shouldAutoRefreshCodexChannelStatus` | 自动刷新任务仍保留；移除未接入状态判定 helper。 |
| ratio | `getHardcodedCompletionModelRatio` | 删除无调用的大段历史倍率/TTS 兼容表，符合 Lite 无 ratio/billing 边界。 |

## 实施中的修正

首次函数边界脚本未能解析复杂签名，未写入该文件；改用 Go AST 位置工具进行声明删除。编译验证发现并清理了三个只由删除项使用的 import：`constant`、`strconv` 和 `time`。
