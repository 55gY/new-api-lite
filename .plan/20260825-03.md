# 上游 P0 协议兼容性修复实施计划

## 执行规则

本计划只实施上游评估报告中确认的 P0 协议兼容性修复：Gemini 模型列表、阿里图片模型映射、阿里可选 `top_p`、Claude 无参数工具与空工具数组、`prompt_cache_key` 透传，以及 Responses penalty 双向保真和 Codex 例外。所有 JSON 编解码必须使用 `common` 封装；不得引入额度、计费、倍率、任务、音视频或多数据库功能。每个 Phase 完成后更新本文件并复核 `plan.md`。

## Current State

当前精简版已具备基本 Models、Chat Completions、Responses、图片 relay 和 Codex relay。上游近期修复已确认六个当前缺口：Gemini 裸 `/v1/models` 路由/鉴权、阿里模型映射协议判断、阿里缺失 `top_p` 时的错误注入、Claude 无参数工具与空工具数组、Chat→Responses 的 `prompt_cache_key`、以及 Chat/Responses 双向 `frequency_penalty`/`presence_penalty` 保真。

## Target State

修复后，精简版应与上游在上述 API 兼容行为上一致，同时保持项目无计费与无多媒体任务的架构边界。每项行为均应有针对性后端回归测试；前端生产构建、Go 全量测试和生产构建均需通过。

## Affected Files

| 范围 | 计划改动 |
| --- | --- |
| `middleware/auth.go`、`router/relay-router.go` | 支持 Gemini 风格裸 `/v1/models` 的 header/query key 鉴权和列表响应。 |
| `relay/channel/ali/*` | 使用映射后的上游模型选择图片协议；仅夹紧显式设置的 `top_p`。 |
| `service/relayconvert/internal/oai_chat/to_claude_messages_req.go` | 标准化 function tool schema、保留无参数工具、仅在有工具时发送 `tools`。 |
| `dto/openai_request.go` 与 `service/relayconvert/**` | 透传 `prompt_cache_key`、`frequency_penalty`、`presence_penalty`。 |
| `relay/channel/codex/adaptor.go` | 清除 Codex 上游不接受的 penalty 字段。 |
| 对应 `*_test.go` | 新增/更新回归测试。 |
| `plan.md`、`.plan/20260825-03.md` | 记录实施和验证。 |

## Rollback Plan / Risks

每个修复均集中在协议转换边界，可通过回滚本次单一提交恢复。Responses DTO 字段必须保留 `json.RawMessage`，以保留显式 `0` 和避免对不受支持的上游进行类型猜测。Claude tool schema 归一化必须只对 `function` tool 生效。Gemini 路由测试不得重新使用 quota 或多数据库测试脚手架。
