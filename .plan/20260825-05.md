# 经典前端健壮性审计与修复计划

## 执行规则

本计划仅针对 `web/classic` 的稳定性、可恢复性与可访问性实施高置信、低风险修复。重点是请求失败可恢复、组件异常不白屏、路由参数稳健性、异步卸载清理、表单提交去重以及构建质量；不进行视觉重设计、不引入新的 UI 框架或依赖、不恢复已移除的计费、音视频、任务或多数据库功能。每个 Phase 完成后更新本文件并复核 `plan.md`。

## Current State

经典前端使用 React 18、React Router 和 Semi Design。已有页面组件、错误提示和 API 请求层，但需要审查全局错误边界、请求取消、页面加载状态、路由守卫与表单重复提交的覆盖情况。前端构建成功但会报告第三方依赖与大 chunk 警告；这些不应在未确认架构收益前直接修改。

## Target State

确认的关键入口将拥有可恢复的错误边界和统一的异步失败反馈；页面卸载后不再由旧请求更新状态；高风险表单操作不会被重复提交；缺失或失效的路由参数会回退到安全页面或可理解的空状态。现有 API 格式、主题与组件库保持不变。

## Rollback Plan / Risks

所有修复必须为局部、可回滚的单一提交。错误边界不能吞掉 API 响应或登录跳转；取消机制不能把真实网络失败误判为静默取消；表单保护不能阻止用户在失败后重新提交。若审计项需要引入新依赖、影响用户流程或修改大范围视觉布局，则不自动实施，转为单独建议。
