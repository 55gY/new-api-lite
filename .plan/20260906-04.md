# 限制配置开关保存异常修复计划

## 执行规则

本计划遵循仓库 `AGENTS.md`。本次只在本地修复、测试并创建中文提交；用户未明确要求时不执行 `git push`。

## Current State

今天新增的 `GlobalApiRateLimitEnable`、`GlobalWebRateLimitEnable`、`CriticalRateLimitEnable` 和 `SearchRateLimitEnable` 使用了 `Enable` 后缀，但后端动态更新逻辑只识别 `Enabled` 后缀，导致开关请求虽然可能写入数据库，内存配置却没有更新，刷新后恢复原状态，表现为无法禁用。新增页面的部分控件还使用 `setInputs({ ...inputs, ... })`，连续点击时存在旧闭包覆盖状态的风险。

## Target State

所有 `*Enable` 与 `*Enabled` 布尔选项都能动态更新；新增设置页面的状态更新使用函数式写法；保存后刷新能够显示后端真实值，并通过回归测试防止再次出现无法禁用。
