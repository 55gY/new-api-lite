# 高置信废弃模块与路由文档清理计划

## 执行规则

- 本计划只处理审计确认无静态引用、无后端路由依赖且不涉及数据库兼容的数据项。
- 每完成一个具体步骤，必须把对应 checkbox 从 `[ ]` 更新为 `[x]`；每完成一个阶段，必须更新本文件并复核 `plan.md`。
- 不处理旧多媒体渠道类型、`/suno` 的 404 墓碑保护、`service/audio.go`、`dto/billing_usage.go`、`/pg` 代理以及任何仍有调用点的组件。
- 最终必须运行前端生产构建、后端全量测试与构建，并检查已清理符号不存在残留引用。

## Current State

- 前端静态引用图确认 14 个模块未被相对导入、动态导入、再导出或 `@/` 别名引用。
- `web/classic/vite.config.js` 的 `/mj` 开发代理未被前后端源码使用。
- `docs/openapi/relay.json` 仍描述已从当前代码中移除的视频与异步任务端点，造成对外文档和实际路由不一致。

## Target State

- 删除所有已确认未接入的 14 个前端模块，并清理对应的无效 CSS 注释。
- 移除 `/mj` 开发代理；保留仍被 playground 使用的 `/pg` 代理。
- 将 OpenAPI relay 文档移除，避免继续对外宣称不存在的视频/异步任务接口；待后续从现行路由重新生成完整规范。
