# 全库健康审计、完整测试与安全清理计划

## 执行规则

本计划以“先测量、再确认、后清理”为原则。所有扫描结果必须区分为已由工具验证的缺陷、高置信静态候选、以及需要真实浏览器会话或生产流量确认的风险。仅自动修复不会改变 API 契约、数据库兼容性、认证流程、精简版功能边界或页面视觉布局的项目。每个 Phase 完成后更新本文件并复核 `plan.md`。

## Current State

当前仓库已通过前后端隔离构建和 Go 全量测试，最近完成 P0/P1 中继稳定性增强与共享前端恢复性修复。仓库仍可能包含编译器不覆盖的未使用符号、不可达前端文件/翻译键、开发依赖、遗留字符串，以及针对断连、定时器、事件订阅、goroutine 和 HTTP body 的生命周期风险。经典前端构建存在第三方 lottie `eval`、过期 Browserslist 数据和大 chunk 警告，需与自有代码问题分开审计。

## Target State

形成可重复的全库健康报告；验证后端全量测试、生产构建、`go vet`、静态检查及前端格式/ESLint/构建；识别并清理已确认的孤立代码、未引用翻译键和冗余直接依赖；审查 goroutine、context、HTTP response body、文件、ticker、timer、事件监听和异步 React 更新的资源生命周期。所有修复均以最小变更提交并通过回归验证。

## Rollback Plan / Risks

清理动作必须保留可回滚的单一提交。Go exported 符号、前端动态 import、运行时通过字符串注册的组件、配置驱动依赖、i18n fallback 以及数据库历史字段均不得仅凭简单 grep 删除。静态检查无法替代浏览器长会话、真实上游网络断连或生产压力测试；这类项目将在报告中明确保留为运行时验证建议。
