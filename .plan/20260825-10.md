# staticcheck 第四批机械修复与兼容性标注计划

## 目标

按处置矩阵实施无行为变化的 map 清理、明确响应写失败策略，并仅为仍需返回兼容弃用 JSON 的旧日志路由添加精确 `SA1019` 忽略。

## 实施结果

| 类别 | 已完成内容 |
| --- | --- |
| 机械化简 | `relay/common/relay_info.go` 删除 6 个冗余 map key 存在性守卫；`relay/common/override.go` 以 `len(nilMap)==0` 简化空 map 判断。 |
| 写失败策略 | Baidu（text/embedding）、Cohere rerank、Zhipu 的响应写错误改为有理由的显式 discard，说明 headers 已发送且客户端断连时无可替代 API 响应。 |
| 兼容性 ignore | 仅对 `/api/log/search` 与 `/api/log/self/search` 的弃用处理器注册添加 `//lint:ignore SA1019`；注释规定访问量观察期结束后应与路由一同删除。 |
| 定向验证 | `go test ./relay/common ./relay/channel/baidu ./relay/channel/cohere ./relay/channel/zhipu ./router` 通过。 |
| 完整验证 | Bun 前端生产构建、Go 全量测试、`go build -trimpath`、`go vet` 与全库 `go test -race` 全部通过。 |
| staticcheck | 物理日志行由 121 降至 108。 |

## 保留项

未将错误文本风格、历史迁移/初始化、cache/quota/TTS、性能 Redis 或高敏感上游 DTO 纳入本批。它们继续保持可见警告，等待专项测试或 API 合约确认，而非添加宽泛 ignore。
