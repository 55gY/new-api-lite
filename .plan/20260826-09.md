# 可选择配置备份与还原计划

## 目标

在 Root 权限的系统设置中提供 **有效配置** 的 JSON 备份和受控还原。用户可逐项选择配置类别；系统账户、API Token、2FA、请求日志、tokens 使用统计、性能指标与 SQLite 数据库文件不属于配置备份范围，绝不导出或导入。

## 备份类别与安全边界

| 类别 | 内容 | 敏感性 | 还原行为 |
| --- | --- | --- | --- |
| `system` | 未归类的有效系统 option、界面、注册、通知与通用运行设置 | 常规 | 仅更新备份内的有效 option。 |
| `model` | `global`、`claude`、`gemini`、`qwen` 分层模型配置 | 常规 | 仅更新备份内的有效 option。 |
| `catalog` | 管理员维护的 Vendor 与 Model 元数据 | 常规且替换性 | 原子替换供应商和模型目录，不包含创建/更新时间或软删除状态。 |
| `operation` | 通用运营、监控、Token 上限与渠道亲和配置 | 常规 | 仅更新备份内的有效 option。 |
| `console` | 控制台内容与导航配置 | 常规 | 仅更新备份内的有效 option。 |
| `performance` | 性能与指标配置 | 常规 | 仅更新备份内的有效 option。 |
| `security` | SSRF、隐私/协议和安全策略配置 | 常规 | 仅更新备份内的有效 option。 |
| `credentials` | SMTP、Turnstile、Worker 等敏感 option | 高敏感 | 默认不选；导出和还原均要求明确敏感确认。 |
| `channels` | 上游渠道连接、模型映射、覆盖规则、分组、优先级和渠道密钥 | 高敏感且破坏性 | 默认不选；还原时原子替换全部渠道与 abilities 配置，要求单独确认。 |

备份 payload 使用版本化 JSON。导出读取运行时 `OptionMap`，因此包含当前生效的默认值和数据库覆盖值；导入仅接受已知的当前有效 option，拒绝账户、Token、日志、统计与历史计费/倍率相关键。渠道备份有意排除已使用 tokens、请求测试结果和其他运行时统计。

## 阶段

- [x] Phase 1：建立版本化 payload、类别筛选、敏感 option 识别与渠道配置投影。
- [x] Phase 2：建立 Root-only 导出与还原接口，执行结构校验、敏感确认、事务性 option 更新和渠道替换后缓存重建。
- [x] Phase 3：增加系统设置“配置备份”标签，提供类别详情勾选、下载、JSON 导入预览与双重确认。
- [x] Phase 4：完成 SQLite model 测试、前端 Bun 构建、全量 Go 测试/build/vet/staticcheck、model race 和 Root HTTP/UI 冒烟；已准备本地提交。

## 验证记录

- SQLite model 测试覆盖类别筛选、敏感凭据隔离、供应商/模型目录替换、渠道配置替换、渠道运行时统计排除、无效 option 拒绝和完整备份的选择性还原。
- Root HTTP 冒烟覆盖类别读取、系统设置导出、敏感类别未确认拒绝、修改后系统设置还原及模型目录导出；页面在真实 Root 会话中验证了九个类别卡片、默认敏感隔离、渠道覆盖告警、下载与 JSON 导入入口。
- 前端 `bun run build`、`go test ./...`、`go build -trimpath ./...`、`go vet ./...`、staticcheck 与 `CGO_ENABLED=1 go test -race ./model -run 'Test(ConfigurationBackup|RestoreConfigurationBackup)'` 均通过。

## 回滚

渠道还原使用数据库事务；任一验证或写入失败都会回滚。系统无法自动恢复已确认完成的渠道覆盖，因此 UI 会提示管理员先下载当前备份，并要求对渠道覆盖和敏感凭据还原分别确认。
