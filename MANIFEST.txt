路径 B（请求头覆盖）配置提示
================================================================
渠道 → 编辑 → 「请求头覆盖」填 JSON，例如：
  {
    "User-Agent": "claude-cli/2.1.39 (external, cli)",
    "x-app": "cli",
    "anthropic-beta": "claude-code-20250219,oauth-2025-04-20"
  }
- UA 具体值以你上游日志报的为准（docker logs 过滤 client/user-agent/unauthorized）
- 渠道测试会跳过 {client_header:...} 占位符与 * / re: 透传规则，必须填静态值
- Claude 中转类上游走 /v1/messages：渠道类型选 Anthropic、端点类型选 anthropic
已实测：header_override 在 SetupRequestHeader 之后应用，可覆盖 User-Agent，
        且渠道测试路径同样生效（OpenAI 与 Anthropic 两种类型均验证通过）。

追加（2026-08-02）：请求头覆盖 一键预填按钮
================================================================
背景：网关默认不设置 User-Agent，Go 运行时会发出 `User-Agent: Go-http-client/2.0`，
      被做客户端门禁的上游判定为未授权客户端（unauthorized_client_error）。

改动：
  web/classic/src/components/table/channels/modals/EditChannelModal.jsx
    在「请求头覆盖」下方新增预填链接「填入 Claude Code 客户端头」，
    与既有「填入模板 / 填入透传模版 / 格式化」并排，点击填入：
      {
        "User-Agent": "claude-cli/2.1.39 (external, cli)",
        "x-app": "cli",
        "anthropic-beta": "claude-code-20250219,oauth-2025-04-20"
      }
  web/classic/src/i18n/locales/zh-CN.json
    补充对应 i18n 词条（仅新增 1 行，未重排原文件）。

设计取舍：刻意**不做全局默认**。header_override 是渠道级配置，若设为全局默认会让
OpenAI / Gemini 等其它渠道也收到 Claude Code 专有头与伪装 UA，可能被那些上游拒绝。
一键预填在省事与安全之间取得平衡；如需“自动生效”，建议改为
“仅当渠道自身 header_override 为空 + 限定渠道类型”的系统级默认（尚未实现）。

验证：前端 vite build 通过；后端 go build（noembed + embed）与 go test ./... 全量通过。
