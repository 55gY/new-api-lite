# auto 自动路由增强实施计划

## 执行规则

- 本计划遵循仓库 `AGENTS.md`，每完成一步更新 checkbox。
- 本阶段只在本地修改、验证和创建中文提交；除非用户明确要求，不推送远程仓库。
- 复用现有 `model_mapping`、渠道能力选择和 relay 重试机制，不新增重复的完整路由系统。
- 不引入计费、额度、倍率、音频、视频或异步任务能力。

## Current State

- 渠道已有 `model_mapping`，方向为实际渠道模型到请求模型。
- `GetChannel()` 已区分直接能力与映射能力，relay 已区分实际模型重试和映射模型重试。
- 渠道/模型存在启用、手动禁用、自动禁用和测试状态相关逻辑。
- 自动测试间隔默认值已调整为 300 分钟。
- 已建立覆盖渠道实际模型的内存预计算候选集、增量刷新、全量清理和短 TTL 最近成功路由。

## Target State

- 新增或更新渠道模型时，仅增量维护 `auto` 的实际模型候选，不覆盖手动映射。
- 模型测试成功或手动启用时恢复候选；手动禁用、自动禁用、测试失败或渠道禁用时立即排除。
- `auto` 请求只解析到真实渠道模型，不进入二次映射，不新增第三层重试。
- 候选集采用内存/Redis 预计算与短 TTL，定时测试完成后做全量校验和失效清理。
- 最近成功模型只在短 TTL 内作为软偏好，并接受可用性、能力、优先级和权重过滤。
- 路由记录选择原因、候选版本、失败切换和候选加入/移除事件。
- 自动测试默认间隔调整为 300 分钟，不覆盖已有数据库配置。

## Rollback Plan / Risks

- 通过 `auto` 总开关关闭新路由，显式模型和原有手动映射继续可用。
- 候选集异常时回退到数据库重建，Redis 仅作为缓存，不作为唯一事实来源。
- 候选更新使用版本号/原子替换，避免并发旧事件覆盖新状态。
- 流式输出开始后不切换上游模型。
- 第三方模型能力不匹配时在请求前排除。
- 最近成功只能短 TTL 软偏好，不能绕过禁用、健康和能力检查。
