# 历史 Lite 契约残留彻底清理

## 执行规则

- 本批移除已不属于 Lite 的任务、quota、货币、价格与签到公开契约，不恢复任何计费、任务或多数据库功能。
- 保留 API token 认证、模型/渠道选择、request count 与 prompt/completion/total tokens 使用统计。
- SQLite 已有数据库中的历史列不做破坏性删除；它们可继续由 GORM 结构映射为内部兼容零值，但不得再作为公开 API 或前端业务字段。
- 每个删除组先清理公开生产者和消费者，再删除无调用配置/模块；不删除被 token 认证或 tokens 统计实际使用的内部字段。

## 审计结论

| 残留组 | 当前问题 | 处置 |
| --- | --- | --- |
| `/api/status` | 暴露 `enable_task`、`quota_per_unit`、货币/汇率、价格与 `checkin_enabled`，但 Lite 已无 task、计费或签到路由 | 移除公开字段及对应前端缓存。 |
| 首次 setup | 创建管理员时写入历史 `Quota: 100000000` | 改为中性零值；数据库列保留兼容。 |
| 前端个人设置 | 孤立的签到日历仍由 status 字段驱动，但后端没有注册签到路由 | 删除组件接入和孤立后端签到 controller/model/setting/migration。 |
| 任务与价格配置 | `TaskEnabled`、`QuotaPerUnit`、新用户/邀请 quota、`Price`、`USDExchangeRate` 仅保留在 option 映射或已无调用的格式化路径 | 移除常量、option 读写映射与无调用设置。旧数据库 option 行保持无害且不再加载。 |
| quota 公开模型 | User/Token 响应仍可能暴露 quota、remain/unlimited/used quota 历史字段 | 公开 JSON 隐藏这些业务字段；token 认证内部仍保留数据库字段和固定 unlimited 兼容值。 |
| 文案 | 前端签到/额度奖励文案和后端签到/quota warning 键成为孤立字符串 | 仅删除已无引用的键和值；不触及 tokens 使用统计文案。 |

## Risks and Rollback

删除 SQLite 物理列会破坏已存在数据库，因此本批只去除业务逻辑和公开 JSON 契约；若 Token 认证依赖 `UnlimitedQuota/RemainQuota` 发生回归，应恢复其内部字段和固定默认赋值，但继续保持其不对外输出。若某个前端历史字段仍被插件或未审计视图读取，先恢复该字段的中性兼容输出，再单独迁移消费者。
