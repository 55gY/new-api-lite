# 渠道新增与编辑表单字段一致性审查计划

## 执行规则

- 审查以 `model.Channel`、后端新增/更新请求绑定和 `EditChannelModal.jsx` 的实际提交载荷为准。
- 先建立字段清单与数据转换链路，再实施最小修复；不引入与渠道表单无关的行为变更。
- 每完成一个 Phase，更新本文件和 `plan.md` 索引状态，并记录验证结果。

## Current State

渠道新增与编辑共用 `EditChannelModal.jsx`。表单同时包含直映射字段、仅用于 UI 的派生字段、写入 `settings`/`setting` JSON 的字段，以及提交前转换为字符串或删除的临时字段。需要逐项确认这些字段不会遗漏、误名、错误写入或以错误类型提交给 `model.Channel`。

## Target State

前端初始值、编辑回填、控件字段名、提交前转换和后端 `Channel` 模型/校验逻辑保持一致。所有 UI 临时字段要么被明确转换到后端字段或 JSON 容器，要么在提交前删除；新增的渠道签到任务关联字段须保持指针/空值语义正确。

## Rollback Plan

本次修复仅调整渠道表单绑定与提交转换。若需回滚，可恢复受影响的前端字段处理和后端校验；不需要迁移或删除现有渠道数据。

## Risks

- `settings`（复数）与 `setting`（单数）用途不同，混写会导致配置丢失或后端解析失败。
- 编辑模式中空密钥、空关联和多 key 字段必须维持原有保留语义，不能因前端默认值覆盖既有数据库值。
- 任何模型、分组或映射的字符串/数组转换差异都可能影响渠道缓存和中继请求。
