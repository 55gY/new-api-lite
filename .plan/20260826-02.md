# 对外错误文本风格警告处理计划

## 结论

五条 `ST1005` 均位于渠道输入校验：四条 Codex OAuth JSON/key 字段校验和一条 Vertex AI key JSON 编码失败。全库前后端、测试和文档检索未发现对原始精确文本的依赖，因此可安全统一为小写开头；字段名、语言、错误条件和 HTTP 处理路径均保持不变。

| 项目 | 结果 |
| --- | --- |
| Codex key 校验 | `Codex` 开头的四条文本改为 `codex`，保留 JSON、`access_token` 和 `account_id` 语义。 |

| 完整隔离回归 | Bun 生产构建、Go 全量测试、`go build -trimpath`、`go vet` 与全库 `go test -race` 均通过。 |
| staticcheck | 日志由 41 行降至 **36**，不再含 ST1005。 |

## 剩余边界

剩余 36 行均为 U1000。它们涉及 Lite quota/cache/TTS 迁移、adapter 协议类型、数据库初始化/迁移、性能 Redis 或 Codex 后台刷新，应在专项测试后决定删除，不能依赖 lint 文本规则直接修改。
